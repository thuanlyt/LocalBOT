## Executive result

The Music backend is functional for the current local-first scope. YouTube is the primary provider and SoundCloud is an optional official OAuth adapter. The native app can search, resolve, show thumbnails, enqueue/play, control the player, select Discord/Windows/both outputs, manage queue state, use Equalizer, manage local playlists through the API, register slash commands, and administer the current Community XP settings/detail/reset slice. The active native runtime no longer injects sample guilds, tracks, queues, playlists, rankings, recent/trending content, or fake playback progress: unavailable data is represented by an explicit offline/empty state.

The most visible regressions were in the native presentation layer. This audit closes the highest-impact issues:

- The five transport controls now have an independent centered layout; the volume popover is positioned separately and cannot push them to the left.
- Guild and voice selection is now available through a global modal from a fixed bottom control bar. Attempting a Discord play action without a voice channel opens that picker automatically.
- Guild/voice state now has a dedicated SSE stream driven by Discord `VoiceStateUpdate`, with silent polling retained as a recovery path. Join/leave responses also reconcile the native state immediately.
- Queue preview and refresh controls now call the real play/refresh paths; they no longer acknowledge an action without changing or re-reading state.
- Switching from Windows-only playback to Discord now requires a real guild/voice context and enqueues the current local track into the Discord player before enabling the second output.
- Native scroll surfaces now use a theme-aware grayscale scrollbar with reserved gutter space, hover/focus-safe contrast, and no hue accents.
- Windows-only discovery and audio no longer require a selected Discord guild or voice channel; the control API exposes global search/audio routes while an optional guild still supplies Equalizer settings.
- Native Music disables unavailable provider filters and playlist source choices from the real `/providers` readiness response. SoundCloud is never presented as ready when its official credentials are absent; the adapter now follows the current URN + `/streams` HLS AAC contract and does not fall back to progressive MP3.
- Removed fixed player audio claims (`320 kbps`, `44.1 kHz`, `Stereo`) that were not part of the backend track contract. The player now shows only provider metadata actually returned by the source.
- Unsupported URLs now fail with a typed provider error instead of being silently treated as a text search query. SoundCloud connection timeouts cover connection setup without aborting a long-running audio body.
- Aborted Windows local-audio requests now cancel their media reader and own FFmpeg pipe errors/backpressure cleanup; a concurrent real-track smoke test no longer reproduces the historical unhandled `write EOF` crash.
- Guild/Voice/Player/provider surfaces now expose an honest freshness state and retry action; SSE events update the timestamp while polling remains recovery-only.
- `LB-MUSIC-019` adds the direct Music guild/channel context flow. The native selector resets on
  guild changes, uses the channel-effective readiness DTO, keeps unknown distinct from denied,
  disables unsupported Stage actions, and revalidates at play/join time. Deterministic helper and
  control-route tests cover ready, overwrite, unknown, Stage, foreign/invalid/missing channels,

## Current implementation coverage

### Music — implemented

- YouTube search, URL/ID resolve, metadata, thumbnail, duration, and safe provider errors.
- SoundCloud search, resolve, thumbnail, duration, and stream using the official API/OAuth adapter when credentials are configured.
- Provider-neutral track model and conservative cross-provider deduplication.
- Queue add, remove, reorder, clear, current track, history, previous, next, shuffle, and repeat `off/all/one`.
- Discord voice output, Windows local output, or both simultaneously.
- Native volume popover, mute, seek for Windows local playback, read-only Discord progress, and Equalizer presets/manual bands.
- Local JSON playlist persistence, native playlist detail management, and slash-command playlist CRUD/track management/play paths.
- Music allow-list/all-members permission mode and slash command registration from the native app.
- Source tags in search results, queue, current track, cards, and slash-command responses.
- Overview recent history, queue preview, and playlists now come only from the active player/API state; there is no fake trending or sample playlist fallback. Discord pending queue recovery is restored from local state after a selected voice session is created, without auto-play.
- Windows-only sessions now honor local previous/skip, shuffle selection, repeat modes, and persisted output/guild selection preferences; discovery and playback do not require joining a Discord voice channel.
- Community progression now applies a bounded guild XP multiplier and largest-match role multiplier, and attempts additive level rewards only for real manageable Discord roles; the native editor and slash commands share the validated settings contract.

### Native app — implemented

- Tauri 2 + React/Vite/TypeScript Windows shell with Be Vietnam Pro.
- Native dev mode with Vite HMR.
- Native app auto-starts and exclusively owns the bot runtime; the bottom control can stop/restart that owned process, while an externally started runtime is shown as unowned and is never adopted or terminated.
- Settings includes an opt-in Windows startup registration backed by the official Tauri autostart plugin; it targets the native executable and does not register `npm` or a bot command.
- Fixed bottom control bar for guild/voice context and bot runtime; top navigation remains dedicated to navigation/theme/settings.
- Health/readiness handling, guild/channel summaries, voice join/leave, slash registration, provider status, audit view, theme persistence, shortcuts, reduced-motion handling, loading/empty/error states, and an honest offline state with no sample runtime data.
- Release preparation now bundles a Windows Node executable, compiled root runtime, and production-only dependencies into a Tauri `runtime` resource. Release Rust launches that resource with app-local `.env` and data paths; the source repository and system Node/npm are no longer required by the packaged runtime path.
- Packaged first-run guidance is implemented in native Settings: when a packaged bridge is offline, the UI shows the real app-local data directory and `.env` presence metadata plus the required variable names. Debug mode does not mislabel the workspace configuration as the packaged setup path.

The `DEMO/` directory remains intentionally UI-only and is excluded from the runtime data path. It is a visual reference, not a source of production data.
